Developed and executed a verification test case to validate correct data capture of the D flip-flop on the rising edge of the clock. Applied multiple input conditions and analysed output transitions to ensure proper data holding behaviour. Repeated the test across different D values to confirm consistent and reliable flip-flop operation.

Design & Interface:
My original design used a plain `always` block with a hardcoded 1-bit signal and no modports on the interface. The AI-optimized version replaced this with `always_ff`, which explicitly tells synthesis and lint tools this is sequential logic — preventing accidental combinational assignments that `always` would silently allow. The reset comparison was simplified from `== 1'b1` to an implicit boolean, and `1'b0` was replaced with `'0` which is width-agnostic. The interface was parameterized with `WIDTH` to make the same module reusable for any data width, modports were added to formally declare signal direction ownership (catching wrong-direction connections at compile time instead of runtime), and two SVA assertions were embedded directly in the interface — one verifying reset behavior, one verifying data propagation using `$past(din)` — both running automatically every clock cycle independent of the scoreboard.

Testbench:
The testbench changes were more significant. My monitor had a subtle but real bug — it created the transaction object once outside the loop, meaning every mailbox entry pointed to the same memory location and would reflect updated values on the next iteration rather than preserving a snapshot. The fix was simply moving `new()` inside the loop. The generator had a missing `()` on `tr.randomize`, meaning it was evaluating a function handle rather than calling it — a silent bug where randomization never actually ran. This was also changed from `$error` to `$fatal` so that a randomization failure halts simulation immediately instead of continuing with invalid stimulus. The scoreboard gained pass/fail counters and a `report()` function that prints a clean summary at end of simulation, and mismatches now use `$error` instead of `$display` so regression tools correctly flag the run as failed. A covergroup was added to the transaction class tracking all four din/dout combinations — without this, 30 passing tests say nothing about whether all input/output scenarios were actually exercised. Finally, a watchdog timer was added to the environment so the simulation fails gracefully with a clear message instead of hanging indefinitely if a mailbox handshake is never satisfied.
